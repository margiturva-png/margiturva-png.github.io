Product

A sales CRM, on every platform

Pipedrive is a sales CRM for small and medium‑sized businesses. The main product is a web app, with a companion native mobile app. In the design system team, my specialism is mobile, and I also contribute to global assets and web app work.

The design team at Pipedrive is around 50 people. Together with developers, they're the design system's users.

02
Tokens

Everything starts with tokens

The design system is built on tokens: base and semantic colours, non‑semantic colours, text styles and elevations, all of which are also available to designers in Figma. In code we also store size, spacing, radius, breakpoint and motion tokens.

For theming we adjust semantic colours and elevations.

I helped create the structure of base and semantic colours to support dark theming, and created the mobile semantic colours, text styles and elevations.

03
Assets

A new icon set of 428 icons

Our visual asset libraries are icons and illustrations, and I've mainly worked on iconography.

During a visual update, Pipedrive decided to create its own icon set for a unified visual language across the product. I led the project. We worked with a freelancer and reviewed their icons weekly, then finalised them with our internal team of a visual designer and an art director.

Along the way we reviewed symbols based on customer feedback, cleaned up the iconography structure and wrote guidelines for creating icons. The library keeps growing and is used across all product platforms.

04
Libraries

Guidelines, components, patterns, templates and specs

I've created mobile guidelines, components, patterns and specs, and contributed to the web app libraries.

Mobile guidelines cover accessibility, offline mode, responsiveness and dark mode. Patterns include navigation, error handling, offline handling, onboarding, loading, empty states and more.

To make documentation consistent, I created the structure for component guidelines, along with the design system architecture scheme, a design system glossary and the Figma file structure.

05
Frameworks

Reusable layouts made of components

Frameworks are the reusable layouts in the product, usually made up of several components.

I've worked on the web app navigation framework, writing guidelines on how to structure the information architecture in navigation and rules for changing the default setup. Every framework includes specs for designers. The navigation framework includes components and responsiveness guidance so they can be reused across product areas.

06
Accessibility

Aiming for WCAG 2.1 AA

Pipedrive aims to comply with the WCAG 2.1 AA standard. To support this, I created accessibility acceptance criteria for the design system that set the standard for creating or updating components.

I also ran a project with two designers and an engineer to audit our component library against the AA level. Based on the audit, we made improvements in both design and code.

Our component guidelines include an accessibility section, and we have accessibility guidelines for both mobile and web.

07
Maintenance

A system that keeps evolving

The design library is revised continuously based on feedback from Pipedrive users and designers, usability testing findings, business requirements, collaboration with the web app design system team, and updates to design tools.

We also support inner sourcing, so product teams can contribute to the design system.

Advocacy

Adoption is part of the work

When building a design system, it's also important to plan how it will be adopted. Besides consulting designers on components, patterns and guidelines, we onboard designers through workshops and presentations. We communicate and document updates and releases, and run quarterly pulse surveys.

As a design system designer I took part in weekly design reviews with product designers and created several workshops and presentations.
